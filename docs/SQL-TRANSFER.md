# انتقال داده‌های سرور قبلی

برای افزودن داده به پروژهٔ فعلی، خروجی «فقط داده» را وارد کنید. فایل‌های دارای `DROP TABLE`، `CREATE TABLE` یا `TRUNCATE` ساختار فعلی را با ساختار بکاپ جایگزین می‌کنند؛ بکاپ قدیمی ممکن است ستون‌هایی مانند `slides.organization_id` را نداشته باشد. کپی فایل‌های تصاویر این اختلاف ساختار را رفع نمی‌کند.

## ترتیب راه‌اندازی

1. پس از کلون، `.env` را با اطلاعات دیتابیس مقصد تنظیم کنید. برای انتقال یک نصب موجود، کلید قبلی `APP_KEY` و فایل‌های `storage/app` را حفظ کنید.
2. از ریشهٔ پروژه اجرا کنید:

```bash
composer install
composer setup
```

3. در phpMyAdmin، دیتابیس مقصد را انتخاب کنید و فایل SQL داده‌ها را از تب Import وارد کنید. فایل انتقال باید جدول `migrations`، نقش‌ها و سازمان‌های پایهٔ تکراری و توکن‌ها و OTPهای قدیمی را کنار بگذارد، ولی وابستگی‌های لازم و رابطهٔ تصاویر با محتوا را نگه دارد. قبل از واردکردن داده روی دیتابیس دارای اطلاعات، از آن خروجی بگیرید.
4. فایل‌های عمومی قدیمی را با همان مسیر نسبی در `storage/app/public` و فایل‌های خصوصی را در `storage/app/private` قرار دهید. `composer setup` پیوند `public/storage` را ایجاد می‌کند. اگر قبلاً همین پیوند صحیح وجود دارد، ساخت دوباره لازم نیست.
5. اجرا کنید:

```bash
php artisan optimize:clear
php artisan serve
```

برای ورود به `/panel/admin/login` از نام کاربری و رمز حساب منتقل‌شده استفاده کنید. رمز هش‌شده باید در ستون `users.password` باقی بماند؛ مقدار رمز داخل `.env` برای ورود استفاده نمی‌شود. اگر SQL شما حسابی ندارد، با `php artisan portal:admin-create` یک حساب جدید بسازید. ساخت مدیر، مرحله‌ای صریح و جدا از Seeder است.

## خروجی‌های شامل ساختار قدیمی

اگر عمداً یک بکاپ کامل را جایگزین کرده‌اید، بعد از Import دوباره `composer setup` را اجرا کنید تا migrationهای ثبت‌نشده اجرا شوند. جدول `migrations` باید با ساختار همان بکاپ هماهنگ باشد؛ ردیف‌های آن را دستی حذف یا از یک بکاپ دیگر جایگزین نکنید.

فایل SQL خصوصی، هش رمز حساب‌ها، اطلاعات اتصال و `.env` را در ریپوی عمومی قرار ندهید. فقط کد و راهنمای انتقال در گیت نگه‌داری می‌شوند.
