# پرتال یکپارچهٔ استانداری مازندران

این نسخه، سایت عمومی، پرتال ۲۲ فرمانداری، پنل شهروندان و پنل مدیریت را در **یک برنامهٔ Laravel 13 با PHP 8.4+، Blade، Tailwind CSS 4 و Alpine.js 3** اجرا می‌کند. فایل‌های CSS، فونت‌ها، تصاویر و ساختار طرح فعلی به پروژه منتقل شده‌اند. وابستگی اجرایی به Next.js یا React وجود ندارد.

فایل‌های آمادهٔ نمایش داخل `public/build` قرار دارند؛ سرور برای اجرای سایت به Node.js نیاز ندارد. Vite فقط ابزار ساخت دارایی‌های همین پروژهٔ لاراول است.

## نسخهٔ لوکال و سرور

شاخهٔ `local-server-ready` برای اجرای استاندارد لاراول آماده است. فایل‌های پیکربندی و راه‌انداز ورسل در این شاخه وجود ندارند؛ هیچ migration، Seeder یا واردکنندهٔ محتوایی هنگام دریافت درخواست HTTP اجرا نمی‌شود. شاخهٔ `master` برای سایت آنلاین فعلی حفظ شده است.

راهنمای کامل مرحله‌به‌مرحله: **[اجرای لوکال، بازیابی SQL و انتقال به سرور](docs/LOCAL-SETUP-FA.md)**.

برای انتقال همان داده‌های سایت، **ابتدا بکاپ کامل SQL را داخل دیتابیس خالی لوکال Import کنید**، اطلاعات همان دیتابیس و `APP_KEY` اصلی را در `.env` بگذارید و فایل‌های storage قبلی را حفظ کنید. سپس:

```bash
composer install
composer setup
php artisan portal:restore-media
php artisan portal:check --database
php artisan serve --host=127.0.0.1 --port=8000
```

`composer setup` پوشه‌ها، کلید غایب، migrationهای اجرا‌نشده و لینک storage را آماده می‌کند و لاگ را عملاً می‌آزماید. کلید موجود، حساب‌ها و رمزهای دیتابیس را عوض نمی‌کند و هیچ Seeder یا importer اجرا نمی‌کند. روی نصب منتقل‌شده `key:generate` نزنید.

بکاپ SQL در `backup-database/ostandari.sql` داخل بستهٔ خصوصی قرار می‌گیرد؛ دادهٔ زنده و اطلاعات خصوصی در Git عمومی منتشر نمی‌شود. [راهنمای بکاپ](backup-database/README.md) مشخص می‌کند چه داده و فایل‌هایی باید همراه انتقال باشند. وجود این README به‌معنای تهیه‌شدن بکاپ نیست.

لاگ محلی در `storage/logs/laravel.log` است:

```bash
php artisan portal:check
tail -f storage/logs/laravel.log
```

برای نصب کاملاً تازه و **بدون بکاپ واقعی**، پس از ساخت دیتابیس خالی و تنظیم `.env`:

```bash
composer setup
php artisan db:seed
php artisan portal:admin-create
```

این مسیر فقط دادهٔ پایه می‌سازد؛ محتوای سایت آنلاین نیست. رمز مدیر با ورودی مخفی دریافت و فقط هش آن در دیتابیس ذخیره می‌شود. `ADMIN_PASSWORD` در `.env` لازم نیست.

برای انتقال به سرور، نمونهٔ `.env.production.example` و بخش سرور در راهنمای کامل را ببینید. Document Root باید `public` باشد و `storage` و `bootstrap/cache` برای PHP قابل نوشتن باشند. Node.js روی سرور اجرا لازم ندارد و خروجی `public/build` کافی است.

## مسیرها

| بخش | مسیر |
| --- | --- |
| صفحه اصلی | `/` |
| فرمانداری نمونه | `/amol`، `/sari` و نامک سایر شهرستان‌ها |
| ورود و ثبت‌نام شهروند | `/login` و `/register` |
| پنل شهروند | `/citizen` |
| ورود مدیریت مرکزی و روابط عمومی استان | `/panel/admin/login` |
| پنل مدیریت | `/panel/admin` |
| ورود روابط عمومی فرمانداری آمل | `/county-admin/amol/login` |
| پنل فرمانداری آمل | `/county-admin/amol` |
| تغییر تصویر شعار سال | `/panel/admin/annual-slogan` |
| تنظیمات عمومی سایت | `/panel/admin/settings` |

مسیرهای فرمانداری برای هر شهرستان با نامک خودش کار می‌کنند. مجوزها و محدودهٔ سازمانی بک‌اند حفظ شده‌اند. حساب شهروندی به پنل مدیریت دسترسی ندارد. نقش روابط عمومی استان همان محدودیت‌های فعلی و استثنای تغییر شعار سال را دارد.

## ورود آزمایشی شهروند با اطلاعات دلخواه

برای آزمایش پنل بدون پیامک، در `.env` قرار دهید:

```dotenv
CITIZEN_DEMO=true
```

سپس `php artisan optimize:clear` اجرا کنید. در این حالت ثبت‌نام و ورود با اطلاعات دلخواه، از مسیر `/register` یا `/login`، پنل آزمایشی شهروند را باز می‌کند. اطلاعات آزمایشی فقط در همان مرورگر نگه‌داری می‌شوند؛ حساب واقعی سرور یا دسترسی مدیریتی ساخته نمی‌شود. برای روند واقعی، مقدار را `false` بگذارید.

در حالت واقعی، پذیرش کامل قوانین ثبت‌نام و تأیید OTP فعال است. تنظیمات ارسال پیامک همان بک‌اند فعلی است: `OTP_DRIVER=http` و مقادیر سرویس پیامک در `.env`. حالت `OTP_DRIVER=log` و نمایش کد توسعه فقط برای local/testing است.

## ویرایش طرح و ساخت دارایی‌ها

قالب‌ها در `resources/views`، استایل‌ها در `resources/css` و رفتارهای Alpine و ماژول‌های مرورگر در `resources/js` هستند. دارایی‌های طراحی فعلی در `public/design` نگه‌داری شده‌اند.

با Node.js 24 و npm، فقط هنگام تغییر این فایل‌ها:

```bash
npm ci
npm run build
```

برای توسعهٔ همراه با بازسازی فوری دارایی‌ها، در دو ترمینال `php artisan serve` و `npm run dev` را اجرا کنید. روی هاست، خروجی `public/build` کافی است.

## آزمون‌ها

آزمون‌های PHP به دیتابیس مجزای **`ostandari_testing`** نیاز دارند؛ کنترل نام دیتابیس در TestCase از اجرای آن‌ها روی دیتابیس برنامه جلوگیری می‌کند.

```bash
php vendor/bin/phpunit
npm test
php artisan view:cache
php artisan route:cache
```

نتیجهٔ بررسی نسخهٔ تحویلی در `docs/MIGRATION-VERIFICATION.md` آمده است. مستندات API بک‌اند در `docs/API.md` و `docs/openapi.json` قرار دارند. فایل‌های SQL داخل `database/imports` صرفاً منابع متنی و نمونهٔ آزمون‌ها هستند و خودکار وارد دیتابیس نمی‌شوند.
