# پرتال یکپارچهٔ استانداری مازندران

این نسخه، سایت عمومی، پرتال ۲۲ فرمانداری، پنل شهروندان و پنل مدیریت را در **یک برنامهٔ Laravel 13 با PHP 8.4+، Blade، Tailwind CSS 4 و Alpine.js 3** اجرا می‌کند. فایل‌های CSS، فونت‌ها، تصاویر و ساختار طرح فعلی به پروژه منتقل شده‌اند. وابستگی اجرایی به Next.js یا React وجود ندارد.

فایل‌های آمادهٔ نمایش داخل `public/build` قرار دارند؛ سرور برای اجرای سایت به Node.js نیاز ندارد. Vite فقط ابزار ساخت دارایی‌های همین پروژهٔ لاراول است.

## نصب اولیه روی سیستم محلی

پیش‌نیاز: PHP 8.4 یا بالاتر، Composer 2 و MySQL 8 یا MariaDB سازگار. افزونه‌های PHP شامل `pdo_mysql`, `mbstring`, `openssl`, `fileinfo`, `ctype`, `curl`, `dom`, `xml`, `tokenizer`, `session`, `exif`, `gd` باشند. `intl` برای تاریخ فارسی توصیه می‌شود.

```bash
composer install
cp .env.example .env
```

در `.env` اطلاعات دیتابیس و `APP_URL` را تنظیم کنید. دیتابیس باید از قبل ایجاد شده باشد. سپس:

```bash
composer setup
php artisan serve
```

دستور `composer setup` پوشه‌های لازم را می‌سازد، کش تنظیمات را پاک می‌کند، فقط در صورت خالی یا غایب‌بودن `APP_KEY` کلید جدید می‌سازد، migrationها و داده‌های پایه را اجرا می‌کند و پیوند `public/storage` را آماده می‌کند. کلید موجود و رمز حساب‌های قبلی حفظ می‌شوند. `APP_KEY` مخصوص هر نصب است و داخل گیت قرار نمی‌گیرد.

نام کاربری و هش رمز مدیر از جدول `users` خوانده می‌شوند؛ `ADMIN_PASSWORD`، `ADMIN_USERNAME` و `ADMIN_EMAIL` در ورود و Seeder استفاده نمی‌شوند. اگر کاربران سرور قبلی را با SQL منتقل می‌کنید، با همان نام کاربری و رمز قبلی وارد شوید. برای ساخت مدیر در یک نصب تازه که هنوز حساب ندارد:

```bash
php artisan portal:admin-create
```

رمز و تکرار آن در ترمینال به‌صورت پنهان پرسیده و فقط هش آن در دیتابیس ذخیره می‌شود. این دستور حساب موجود را بازنشانی نمی‌کند. سایت در `http://127.0.0.1:8000` و ورود مدیر در `/panel/admin/login` است. برای افزودن محتوای متنی رسمیِ همراه پروژه به دیتابیس تازه، پس از ساخت مدیر، به‌صورت اختیاری:

```bash
php artisan db:seed --class=OfficialPublicSiteSeeder
```

Seeder رسمی، دادهٔ زندهٔ سرویس فعلی نیست. `DemoSeeder` نیز فقط برای دادهٔ نمونه است و در روند نصب بالا اجرا نمی‌شود.

## ارتقای دیتابیس پس از واردکردن بکاپ قدیمی

پس از کلون پروژه، اطلاعات اتصال دیتابیس واردشده را در `.env` تنظیم کنید و از ریشهٔ پروژه اجرا کنید:

```bash
composer install
composer setup
php artisan serve
```

اجرای `db:seed` به‌تنهایی ساختار دیتابیس را ارتقا نمی‌دهد. دستور `composer setup` ابتدا ستون‌هایی مانند `slides.organization_id` و سایر تغییرات بعدی را با migrationهای پروژه اضافه می‌کند و سپس Seeder را اجرا می‌کند. جدول‌ها و داده‌های موجود حذف نمی‌شوند؛ از `migrate:fresh` یا حذف دستی جدول‌ها استفاده نکنید.

Seeder فقط نقش‌ها و سازمان‌های پایه را آماده می‌کند و حساب و رمز کاربران واردشده از SQL را تغییر نمی‌دهد. هنگام انتقال یک نصب موجود، `.env`، `APP_KEY` و فایل‌های `storage/app` قبلی را حفظ کنید. راهنمای انتقال داده بدون جایگزین‌کردن ساختار جدول‌ها در `docs/SQL-TRANSFER.md` آمده است.

## جایگزینی کد روی سرویس فعلی چابکان

این بسته شامل کد و دارایی‌های طراحی است؛ دیتابیس زنده، فایل‌های شخصی کاربران، `.env` و رمزهای سرویس در آن قرار ندارند.

1. هنگام قراردادن کد در پوشهٔ جدید، `.env` فعلی و فایل‌های `storage/app` سرویس خود را حفظ یا منتقل کنید. نام و اتصال دیتابیس باید همان مقادیر فعلی بمانند. `APP_KEY` موجود را تغییر ندهید.
2. ریشهٔ وب‌سرور را روی پوشهٔ `public` همین پروژه قرار دهید. پوشه‌های `storage` و `bootstrap/cache` باید برای کاربر PHP قابل نوشتن باشند.
3. `APP_URL` را برابر نشانی نهایی سایت، `APP_ENV=production` و `APP_DEBUG=false` تنظیم کنید. در HTTPS از `SESSION_SECURE_COOKIE=true` استفاده کنید.
4. از ریشهٔ پروژه اجرا کنید:

```bash
composer install --no-dev --optimize-autoloader
php artisan optimize:clear
php artisan migrate --force
php artisan storage:link
php artisan optimize
```

اگر `public/storage` از قبل پیوند صحیحی به `storage/app/public` دارد، ساخت دوبارهٔ آن لازم نیست. در سرویس موجود به اجرای Seederها، فایل‌های SQL نمونه یا ایجاد دوبارهٔ کلید برنامه نیازی نیست. از `migrate:fresh` استفاده نکنید؛ مایگریشن‌های بک‌اند فعلی حفظ شده‌اند.

در این ساختار `BACKEND_URL`، پراکسی Next.js یا سرور Node جداگانه لازم نیست. سایت و پنل روی همان دامنهٔ لاراول اجرا می‌شوند. API خارجی فعلی در `/api/v1` نیز باقی مانده است.

## مسیرها

| بخش | مسیر |
| --- | --- |
| صفحه اصلی | `/` |
| فرمانداری نمونه | `/amol`، `/sari` و نامک سایر شهرستان‌ها |
| ورود و ثبت‌نام شهروند | `/login` و `/register` |
| پنل شهروند | `/citizen` |
| ورود مدیریت مرکزی و روابط عمومی استان | `/panel/admin/login` |
| پنل مدیریت | `/panel/admin` |
| ورود روابط عمومی فرمانداری آمل | `/county-admin/amol/login` |
| پنل فرمانداری آمل | `/county-admin/amol` |
| تغییر تصویر شعار سال | `/panel/admin/annual-slogan` |
| تنظیمات عمومی سایت | `/panel/admin/settings` |

مسیرهای فرمانداری برای هر شهرستان با نامک خودش کار می‌کنند. مجوزها و محدودهٔ سازمانی بک‌اند حفظ شده‌اند. حساب شهروندی به پنل مدیریت دسترسی ندارد. نقش روابط عمومی استان همان محدودیت‌های فعلی و استثنای تغییر شعار سال را دارد.

## ورود آزمایشی شهروند با اطلاعات دلخواه

برای آزمایش پنل بدون پیامک، در `.env` قرار دهید:

```dotenv
CITIZEN_DEMO=true
```

سپس `php artisan optimize:clear` اجرا کنید. در این حالت ثبت‌نام و ورود با اطلاعات دلخواه، از مسیر `/register` یا `/login`، پنل آزمایشی شهروند را باز می‌کند. اطلاعات آزمایشی فقط در همان مرورگر نگه‌داری می‌شوند؛ حساب واقعی سرور یا دسترسی مدیریتی ساخته نمی‌شود. برای روند واقعی، مقدار را `false` بگذارید.

در حالت واقعی، پذیرش کامل قوانین ثبت‌نام و تأیید OTP فعال است. تنظیمات ارسال پیامک همان بک‌اند فعلی است: `OTP_DRIVER=http` و مقادیر سرویس پیامک در `.env`. حالت `OTP_DRIVER=log` و نمایش کد توسعه فقط برای local/testing است.

## ویرایش طرح و ساخت دارایی‌ها

قالب‌ها در `resources/views`، استایل‌ها در `resources/css` و رفتارهای Alpine و ماژول‌های مرورگر در `resources/js` هستند. دارایی‌های طراحی فعلی در `public/design` نگه‌داری شده‌اند.

با Node.js 24 و npm، فقط هنگام تغییر این فایل‌ها:

```bash
npm ci
npm run build
```

برای توسعهٔ همراه با بازسازی فوری دارایی‌ها، در دو ترمینال `php artisan serve` و `npm run dev` را اجرا کنید. روی هاست، خروجی `public/build` کافی است.

## آزمون‌ها

آزمون‌های PHP به دیتابیس مجزای **`ostandari_testing`** نیاز دارند؛ کنترل نام دیتابیس در TestCase از اجرای آن‌ها روی دیتابیس برنامه جلوگیری می‌کند.

```bash
php vendor/bin/phpunit
npm test
php artisan view:cache
php artisan route:cache
```

نتیجهٔ بررسی نسخهٔ تحویلی در `docs/MIGRATION-VERIFICATION.md` آمده است. مستندات API بک‌اند در `docs/API.md` و `docs/openapi.json` قرار دارند. فایل‌های SQL داخل `database/imports` صرفاً منابع متنی و نمونهٔ آزمون‌ها هستند و خودکار وارد دیتابیس نمی‌شوند.
